# AI 工具场景配方

## 受众与使用场景

- 受众：刚开始使用 AI 的普通用户、内容创作者、轻量办公与技术从业者。
- 适用：同类工具怎么选、单个 Skill 怎么用、一个 AI 工作流如何跑通、近期工具动态如何核验。
- 不适用：没有真实任务的十大必装、只按安装量或星标排序、用淘汰焦虑推动安装。

## 三个标题公式

1. `具体问题 + 数量 + 明确结果`：`查近 30 天热点：6 个 Skill 分别负责什么`
2. `工具 A / B / C + 怎么选 + 分层标准`：参考 `ai-tools-02`。
3. `一个工具 + 一个成品 + 限定条件`：`用 Agent 做 60 秒荐书视频：输入、流程和人工检查`。

## 三种方向原型

### A. 同任务横评

固定输入、模型、设备和输出格式，比较 5 至 8 个同类工具。必须公开评价维度，并按人群分结论。参考 `ai-tools-01`、`ai-tools-04`、`ai-tools-05`。

### B. 单 Skill 跑通

只讲一个任务：来源、安装、第一次调用、可直接问什么、失败怎么排查。参考 `ai-tools-06`、`ai-tools-16`。

### C. 工作流复盘

从具体成品倒推输入、自动步骤、人工校对和结果，不把全自动当卖点。参考 `ai-tools-10`、`ai-tools-20`。

## 推荐 7 页结构

1. 封面：一个具体问题、工具数量和读者能得到的结果。
2. 选择地图：每个工具只解决哪一步。
3. 工具 1-2：做什么、什么时候用、可以直接问什么。
4. 工具 3-4：沿用同一信息层级，避免突然堆参数。
5. 工具 5-6：补充限制、成本或安装条件。
6. 一条可复制的组合提示词，附预期输出格式。
7. 安装与安全：仓库、最近更新、脚本权限、账号/Cookie/API Key 测试环境。

## 文案节奏

- 封面 12 至 22 字，优先任务词：查、选、做、核对、复盘。
- 每个工具最多三段：`做什么`、`什么时候用`、`可以直接问`。
- 参数和安装量只放小字，不承担主要说服任务。
- 保留一条反方判断，例如谁暂时不用装；参考 `ai-tools-18`。
- 禁用：`十大必装`、`避免被时代淘汰`、`夯爆`、`效率翻倍`。反例见 `ai-tools-08`、`ai-tools-09`。

## 图片策略与缺图处理

- 横评页优先自制任务流程图、评价矩阵和本地实测结果，不拼工具 Logo 墙。
- 单工具页可使用官方仓库首页的短引用信息，但不复制项目截图作为整页背景。
- 成品工作流用自生成或自有素材展示输入与输出。
- 缺少实测图时，改用文字卡、命令片段和空状态示意；明确标注“未核验界面”，不得生成一个仿真产品截图冒充实测。

## Guizang 路由

- **Swiss**：工具横评、步骤、安装命令、权限矩阵、输入输出对照。用高对比网格和短标签。
- **Editorial**：新工具故事、普通人采用障碍、一次工作流复盘。用大标题、留白和一张真实主视觉。
- 同一组卡只选一个主路由；安装末页可局部使用 Swiss 命令区。

## 安全与版权

- 第三方 Skill 安装前检查仓库来源、最近更新时间、许可证和脚本权限。
- 涉及账号、Cookie、API Key 或浏览器控制时，先在测试账号和测试数据运行，不在图片中展示配置原文。
- 星标、安装量和版本号在发布当天复核，并标注日期。
- 不复制完整教程、提示词包、仓库文档或他人生成图；只保留短引用和自己的实测分析。

## 发布前检查

- [ ] 标题写了具体问题、数量与结果。
- [ ] 每个工具都有使用时机和一句可直接问。
- [ ] 横评使用同一任务和环境。
- [ ] 至少写一个限制或不适合人群。
- [ ] 安装来源、更新、权限和密钥风险已说明。
- [ ] 没有必装、淘汰、倍数效率或爆款承诺。
